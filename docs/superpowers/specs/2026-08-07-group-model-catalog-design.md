# 按分组模型列表驱动模型广场与图片工作台

## 背景

当前模型广场和图片工作台通过活跃渠道聚合模型。部署环境的渠道列表为空，但分组已经维护了 `models_list_config`，导致两个功能无法展示可用模型。本变更将分组模型列表作为这两个功能的模型目录来源，并保留现有用户权限和 API Key 安全边界。

## 目标

- 模型广场和图片工作台完全不依赖渠道数据。
- 模型名称来自活跃分组的 `models_list_config.models`。
- `models_list_config.enabled=false` 或模型列表为空的分组不参与展示。
- 模型广场只展示公开分组（`is_exclusive=false`）。
- 图片工作台只展示用户有权限且 `allow_image_generation=true` 的分组，并继续要求该分组下存在可用 API Key。
- 使用内置官方模型价格，并叠加分组/用户倍率、图片独立倍率和当前充值倍率。
- 不新增数据库迁移，不修改既有表结构和已有渠道功能。

## 非目标

- 不删除、修改或迁移渠道数据。
- 不改变 API Key、分组权限、订阅权限和请求路由的判定逻辑。
- 不把模型列表配置扩展为新的数据库字段。

## 设计

### 分组模型目录

`ChannelService.ListPlazaGroups` 改为读取活跃分组并从每个分组的 `models_list_config` 构造模型条目，不再调用渠道仓储或读取渠道关联。模型名称去重、去除空白，并按名称排序；分组按现有倍率和名称排序。

每个模型的基础展示价格由现有 `PricingService` 的内置/同步官方价格生成。渠道定价为空时，不应导致模型消失。无法从官方目录解析价格的模型仍可展示名称，但价格字段为空。

### 模型广场

Handler 在返回结果前固定过滤 `is_exclusive=true` 的分组，无论请求是否带登录态。公开分组的倍率和用户倍率仍按现有逻辑返回。

前端模型广场读取支付配置中的 `balance_recharge_multiplier`，替代硬编码充值换算常量。展示价格使用官方基础价格乘有效倍率，再按充值倍率换算为用户展示货币。图片模型优先使用图片独立倍率规则。

### 图片工作台

图片工作台配置目录复用新的分组模型目录，但只保留：

1. 当前用户可绑定的活跃分组；
2. `allow_image_generation=true` 的分组；
3. `models_list_config.enabled=true` 且包含受支持图片模型的分组。

保存配置和生成请求仍使用用户当前可用的 API Key，并校验 API Key 与分组的归属关系。渠道为空不会绕过 API Key 或权限检查。

## 数据流

```text
活跃分组
  -> models_list_config.models
  -> 官方 PricingService 补充基础价格
  -> 模型广场：过滤公开分组 + 应用展示倍率
  -> 图片工作台：过滤用户可用 + allow_image_generation + 图片模型
```

## 测试与验收

- 服务层：无渠道时能从启用的分组模型列表生成模型广场条目。
- 服务层：禁用 `models_list_config`、空列表和重复模型的行为符合设计。
- Handler：模型广场永远过滤专属分组，登录和匿名结果均验证。
- 图片服务：只返回允许生图的用户可用分组，并拒绝不属于该分组的 API Key。
- 价格：官方价格、分组倍率、用户倍率、图片独立倍率和充值倍率计算覆盖正常及缺失价格场景。
- 回归：现有渠道服务、API Key 权限和数据库迁移校验测试保持通过。

## 部署约束

构建新镜像并只替换应用容器；PostgreSQL 和 Redis 容器、数据卷与配置保持不变。发布前备份 Compose 配置，发布后验证应用健康检查和模型广场/图片工作台接口。
